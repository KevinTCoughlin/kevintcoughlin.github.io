    Pillow's convert() kept the camera GPS on the published original

    In Bauhaus, embed_exif started from image.getexif() and only overwrote title, artist, and copyright. Image.convert("RGB") keeps the source EXIF, so /api/<date>/original was published with the camera's GPS IFD, body serial number, and maker notes. That is the file the Atom feed links as "Original". Unsplash photos, which the scheduled run uses when both museum sources fail, commonly carry GPS. The change is bauhaus#200 (7be86a6).

    Bad publisher feeds were opening the circuit breaker for iTunes

    Five broken publisher feeds in a row used to open the circuit breaker in podr-service for 30 seconds. Search (/?q=), top podcasts (/?q=toppodcasts), and /podcast/{id} share that breaker with iTunes and Podcast Index, so they returned 500, or a cached entry still inside ttl + STALE_SECONDS. The log called the publisher failure an iTunes API error.
